 OAuth 2.0 — це якраз той самий стандартний протокол, за допомогою якого сторонні додатки безпечно "коннектяться" до Google API 
 (наприклад, до Google Drive, Gmail, YouTube) або дозволяють вам входити на сайти через кнопку «Увійти через Google»

OAuth 2.0

Тут починається плутанина.

OAuth 2.0 — це не authentication protocol у первинному сенсі.

OAuth відповідає на питання:

Як application отримує обмежений доступ до resource від імені user?

Наприклад:

Your application
      │
      │ "I need access to Google Calendar"
      ▼
Authorization Server
      │
      ▼
Access Token
      │
      ▼
Google API

OAuth визначає authorization delegation.



OpenID Connect
Говорячи просто, OAuth 2.0 відповідає за авторизацію (доступ до даних), а OpenID Connect (OIDC) відповідає за автентифікацію (перевірку особи користувача).

OIDC побудований поверх OAuth 2.0.

Він додає:

Authentication / identity layer.

Тобто:

OAuth 2.0
    +
Identity
    =
OpenID Connect

Саме тому:

OAuth != OIDC




Refresh Token

Access token часто короткоживучий:

expires in 5–60 minutes

Refresh token дозволяє отримати новий access token без повторного login.

Access Token
     │
     ▼
expires
     │
     ▼
Refresh Token
     │
     ▼
New Access Token

Refresh tokens потребують особливої уваги до security.
